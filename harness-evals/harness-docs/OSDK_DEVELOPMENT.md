# Operator SDK Development Guide

## Prerequisites

| Prerequisite | Version | Notes |
|---|---|---|
| Go | 1.26.3+ | See `go.mod` |
| make | any | Build system |

All other tools (golangci-lint 2.9.0, KIND 0.29.0, kubectl) are fetched automatically by Makefile targets.

## Setup

```bash
make setup              # Bootstrap: fetch submodules, Go modules, lint tools
```

This initializes the `website/` submodule, downloads Go modules, and installs the pinned lint tooling. No cluster is required.

## Build Commands

| Command | Purpose |
|---|---|
| `make build` | Build `operator-sdk` and `helm-operator` to `build/` |
| `make build/operator-sdk` | Build operator-sdk only |
| `make build/helm-operator` | Build helm-operator only |
| `make install` | Install binaries to `$GOBIN` |
| `make image-build` | Build all container images |

## Verification

| Command | Purpose |
|---|---|
| `make verify` | Full pre-PR gate: test-sanity + test-unit + build + file-size check |
| `make verify-file FILE=path` | Fast single-file check (format, vet, lint, package tests) |
| `make test-sanity` | Format, lint, license, error format checks + `git diff --exit-code` |
| `make test-unit` | Unit tests with race detection |
| `make test-static` | All non-cluster tests (sanity + unit + docs) |
| `make test-docs` | Validate changelog and check doc links |
| `make test-e2e` | E2E tests (requires KIND cluster) |
| `make lint` | Run golangci-lint (read-only) |
| `make fix` | Auto-fix: go mod tidy, go fmt, golangci-lint --fix |
| `make generate` | Regenerate CLI docs, samples, testdata |
| `make bindata` | Update embedded OLM data |
| `make precommit` | Run pre-commit hooks on all files |
| `make check-file-size` | Check first-party Go files against size limit |

## Build Tag Requirement

All Go commands require `-tags containers_image_openpgp`. The Makefile sets this automatically via `GO_BUILD_TAGS`. If running `go` directly:

```bash
go build -tags containers_image_openpgp ./...
go test -tags containers_image_openpgp ./...
go vet -tags containers_image_openpgp ./...
```

## CGO Settings

- **Production builds**: `CGO_ENABLED=0` (always)
- **Unit tests**: `CGO_ENABLED=1` with `-race` flag

## Code Style Conventions

### Import Ordering

Enforced by `goimports`. Three groups separated by blank lines:

```go
import (
    // 1. Standard library
    "context"
    "fmt"

    // 2. Third-party packages
    "github.com/spf13/cobra"
    "k8s.io/apimachinery/pkg/apis/meta/v1"

    // 3. Internal packages
    "github.com/operator-framework/operator-sdk/internal/util"
)
```

### Error and Log Message Formatting (CI-enforced)

Checked by `hack/check-error-log-msg-format.sh`:

- **Log messages** (`.Error()`, `.Fatal()`, `.Info()`, `.Warn()`): MUST start with uppercase
- **Error messages** (`errors.New()`, `fmt.Errorf()`): MUST start with lowercase, MUST NOT end with punctuation

### License Header (CI-enforced)

Every `.go` file must contain `Copyright`, `generated`, `GENERATED`, or `Licensed` in its first 3 lines. Standard Apache 2.0 header. Files in `internal/bindata/` are exempt.

### Dot Imports

Allowed **only** for Ginkgo and Gomega in test files. All other dot imports are forbidden.

### Generated Files — Do Not Edit

- `zz_generated*` prefix files
- Files with `DO NOT EDIT` or `Code generated` headers
- `internal/bindata/` (regenerate with `make bindata`)
- `testdata/` (regenerate with `make generate`)
- `*fakes/` directories (generated by counterfeiter)

## Downstream Fork Conventions

### Commit Message Prefixes

- `UPSTREAM: <carry>:` — Persistent downstream changes
- `UPSTREAM: <drop>:` — Temporary commits regenerated on each rebase
- `<subsystem>: <what changed>` — Regular upstream-style (max 70 chars)

### Vendor Directory

After changing `go.mod`:
1. `go mod tidy`
2. `go mod vendor`
3. Commit vendor changes separately with `UPSTREAM: <drop>: Update vendor directory`

### Patch System

Downstream patches in `patches/` are applied by `make -f ci/prow.Makefile patch`.

### Changelog

User-facing PRs require a YAML fragment in `changelog/fragments/`. See `changelog/fragments/00-template.yaml`.

## Linting

Configured in `.golangci.yml` (v2 format). Enabled linters: `dupl`, `ginkgolinter`, `goconst`, `gocyclo`, `gosec`, `misspell`, `nakedret`, `revive`, `unconvert`, `unparam`, `depguard`.

Excluded gosec rules: G110, G601, G404, G204, G306.

## Common Pitfalls

1. **Forgetting the build tag**: All Go commands require `-tags containers_image_openpgp`.
2. **Editing generated files**: Edit the generator/template instead.
3. **Running `go mod tidy` without vendoring**: Always follow with `go mod vendor`.
4. **Mixing log frameworks**: logrus for CLI, logr for controller runtime.
5. **Uppercase error messages**: Error strings start lowercase, no trailing punctuation.
6. **Direct Docker usage in CI**: Downstream CI has no Docker; use `podman`.
7. **Editing patches directly**: Modify the source and regenerate with `diff -up`.
8. **Missing changelog fragments**: Required for user-facing PRs.

## CI Configuration

- **GitHub Actions** (`.github/workflows/`): `quality-gate.yml` is the primary required gate.
- **OpenShift Prow** (`ci/prow.Makefile`): Downstream CI; always applies patches before builds.
- **Security scanning** (`security.yml`): govulncheck, OSV scan, Trivy image scan.
