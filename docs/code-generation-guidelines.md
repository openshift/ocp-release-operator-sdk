# Code Generation Guidelines

## Overview

This repository uses multiple code generation systems: kubebuilder machinery for scaffolding, CSV/bundle generators for OLM packaging, `go-bindata` for embedding manifests, `counterfeiter` for test fakes, `controller-gen` for deepcopy and marker help, and cobra/doc for CLI documentation. All generation runs through `make generate`.

## Makefile `generate` Target

The `make generate` target is the single entry point. It runs, in order:

1. `hack/generate/cncf-maintainers/main.go` -- maintainer list
2. `hack/generate/cli-doc/gen-cli-doc.go` -- CLI reference docs under `website/content/en/docs/cli/`
3. `hack/generate/samples/generate_testdata.go` -- testdata samples under `testdata/`
4. `go generate ./...` -- all `//go:generate` directives

Always run `make generate` after changing APIs, markers, CLI commands, or generator interfaces. CI enforces `git diff --exit-code` after generation via `test-sanity`.

## Kubebuilder Machinery Templates

Scaffold templates live under `internal/plugins/` and implement `machinery.Template` from `sigs.k8s.io/kubebuilder/v4/pkg/machinery`.

### Template struct pattern

Every template must:

- Embed `machinery.TemplateMixin` (and optionally `machinery.ProjectNameMixin`, `machinery.ResourceMixin`)
- Assert interface compliance: `var _ machinery.Template = &MyTemplate{}`
- Implement `SetTemplateDefaults() error`, setting `f.Path`, `f.IfExistsAction`, and `f.TemplateBody`

```go
var _ machinery.Template = &Kustomization{}

type Kustomization struct {
    machinery.TemplateMixin
    machinery.ProjectNameMixin
}

func (f *Kustomization) SetTemplateDefaults() error {
    if f.Path == "" {
        f.Path = filepath.Join("config", "manifests", "kustomization.yaml")
    }
    f.IfExistsAction = machinery.SkipFile
    f.TemplateBody = kustomizationTemplate
    return nil
}
```

### IfExistsAction values

- `machinery.SkipFile` -- use for files users may customize (kustomization.yaml, samples)
- `machinery.OverwriteFile` -- use for files that are fully regenerated (watches.yaml via Inserter)
- `machinery.Error` -- use when a file must not already exist

### Inserter pattern for appending to files

To add content to existing scaffold markers, implement both `machinery.Template` and `machinery.Inserter`. Provide `GetMarkers()` and `GetCodeFragments()`. Define marker constants and use `machinery.NewMarkerFor(path, markerName)`.

### Scaffold execution

Always use `machinery.NewScaffold` with explicit permissions:

```go
scaffold := machinery.NewScaffold(fs,
    machinery.WithDirectoryPermissions(0755),
    machinery.WithFilePermissions(0644),
    machinery.WithConfig(s.config),
    machinery.WithResource(s.resource),
)
```

### Plugin naming

SDK plugins use the qualifier `.sdk.operatorframework.io` (defined in `internal/plugins/plugins.go`). Plugin keys follow the form `<name>.sdk.operatorframework.io/v<N>`.

## Operator-SDK CSV Markers

The marker prefix is `+operator-sdk:csv:customresourcedefinitions`. The root prefix `operator-sdk` is defined in `internal/markers/markers.go`.

### Type-level marker (on CRD type declarations)

```go
//+operator-sdk:csv:customresourcedefinitions:displayName="My Resource",resources={{Pod,v1,my-pod},{Service,v1}}
```

### Field-level marker (on spec/status struct fields)

```go
//+operator-sdk:csv:customresourcedefinitions:type=spec,displayName="Size",xDescriptors="urn:alm:descriptor:com.tectonic.ui:podCount"
```

Field markers accept: `type` (spec|status), `displayName`, `xDescriptors` (comma-separated), `order`.

### Generated marker help

`zz_generated.markerhelp.go` is produced by the `+controllertools:marker:generateHelp` directive on marker struct types. Do not edit it.

## CSV Generation Pipeline

The generation flow for `operator-sdk generate bundle`:

1. **Collect**: `collector.Manifests` walks input directories, parsing YAML into typed fields (Deployments, Roles, CRDs, Webhooks, etc.)
2. **Base**: A CSV base is loaded from `config/manifests/bases/<name>.clusterserviceversion.yaml`, or created empty via `bases.New()`
3. **Apply**: `ApplyTo()` merges collected manifests into the CSV -- RBAC to permissions, Deployments to install strategy, CRDs to owned descriptions, webhooks to webhook definitions
4. **Write**: The CSV is written as `<name>.clusterserviceversion.yaml` using the naming convention `<operator>.v<semver>`

## Generated File Conventions

### DO NOT EDIT headers

Three distinct header formats exist in this repo:

| Generator | Header |
|-----------|--------|
| controller-gen | `// Code generated by controller-gen. DO NOT EDIT.` |
| go-bindata | `// Code generated for package <pkg> by go-bindata DO NOT EDIT. (@generated)` |
| counterfeiter | `// Code generated by counterfeiter. DO NOT EDIT.` |

controller-gen files also include `//go:build !ignore_autogenerated`.

### zz_generated prefix

Files named `zz_generated.*.go` are fully machine-generated. Do not edit them. They sort last alphabetically, making them easy to identify in directory listings.

### License header enforcement

`hack/check-license.sh` checks that all `.go` files (excluding `internal/bindata/`) have `Copyright`, `generated`, `GENERATED`, or `Licensed` in the first 3 lines. Generated files satisfy this via their generator headers.

## go:generate Directives

The repo uses `counterfeiter` for generating test fakes:

```go
//go:generate go run github.com/maxbrunsfeld/counterfeiter/v6 . Generator
```

The tool dependency is pinned in `tools/tools.go` with a build tag `// +build tools`. Generated fakes go into a `*fakes/` subdirectory.

## OLM Bindata Generation

`hack/generate/olm_bindata.sh` downloads OLM release manifests and embeds them via `go-bindata` into `internal/bindata/olm/manifests.go`. Run via `make bindata`. The output file is excluded from license checking.

## Testdata Sample Generation

`hack/generate/samples/generate_testdata.go` regenerates the `testdata/` directory by invoking the `operator-sdk` binary to scaffold complete Go and Helm sample projects. Samples are organized under `testdata/<type>/<version>/<project-name>/`.

Key conventions:

- Sample generators set `KUBECONFIG=broken_so_we_generate_static_default_rules` to ensure idempotent RBAC generation
- Timestamps like `createdAt` are replaced with fixed values for reproducibility
- Bundle annotations are stripped to avoid environment-dependent differences

## CLI Documentation Generation

`hack/generate/cli-doc/gen-cli-doc.go` uses `cobra/doc.GenMarkdownTreeCustom` to generate markdown docs. It:

- Deletes and recreates the output directory to remove stale files from renamed/removed commands
- Preserves `_index.md` across regeneration
- Replaces angular brackets with HTML entities in long descriptions
- Adds Hugo front matter with `title` metadata

## Kustomize Integration

The `config/manifests/` directory is the integration point between kustomize and OLM generation:

- `bases/<name>.clusterserviceversion.yaml` -- the CSV base (generated, but user-customizable)
- `kustomization.yaml` -- references bases, default config, samples, and scorecard

The bundle generation pipeline runs: `kustomize build config/manifests | operator-sdk generate bundle`. This is encoded in the Makefile `bundle` target scaffolded by the manifests plugin.

## File Naming Conventions

| Artifact | Pattern |
|----------|---------|
| CRD files | `<group>_<plural>.yaml` |
| CSV files | `<name>.clusterserviceversion.yaml` |
| CR samples | `<group>_<version>_<kind>.yaml` |
| Deepcopy | `zz_generated.deepcopy.go` |
| Marker help | `zz_generated.markerhelp.go` |
| Test fakes | `<package>fakes/fake_<interface>.go` |

## Adding a New Scaffold Template

1. Create a Go file under the appropriate `internal/plugins/<type>/<version>/scaffolds/internal/templates/` path
2. Define a struct embedding `machinery.TemplateMixin` and any needed mixins
3. Assert `var _ machinery.Template = &YourTemplate{}`
4. Implement `SetTemplateDefaults()` with path, exists-action, and template body
5. Register the template in the parent scaffolder's `Execute()` call
6. If the template needs to append to existing files, also implement `machinery.Inserter`
